# Contributing

Thanks for wanting to help improve this guide.

## Report a mistake

If you find an error in a definition, open an issue using the "Content correction" template. Include:

- The term name
- What the current text says
- What you think it should say
- A source if you have one (IBM documentation, your own experience, a book)

## Suggest a new term

Open an issue using the "New term suggestion" template. Include:

- The term name
- The module it belongs to
- A plain-English definition (your own words, not copied from IBM docs)
- A Riverbend Water example if you can think of one

## Submit a pull request

1. Fork the repository
2. Create a branch: `git checkout -b fix/term-name`
3. Make your changes
4. Run `npm run build-content` and `npm run build` to check for errors
5. Open a pull request with a clear description of what changed and why

### What we accept

- Corrections to existing term definitions
- New terms that fit within the 14 modules
- Improvements to examples
- Better Riverbend Water examples
- Fixes to broken internal links

### What we do not accept

- Content copied from IBM documentation without attribution
- Marketing language or hype phrases
- Changes to the code or build system without discussion

## Review process

All content changes are reviewed before merging. A Maximo practitioner will check the definition for accuracy. This may take time.

## Code of conduct

Be respectful. Critique the content, not the person. Corrections are welcome; arguments are not.
